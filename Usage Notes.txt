Min Conf means minimum detection confidence.

Before every Follow Step, FabScan looks at the camera image and tries to detect the line/edge inside the search box. It then gives that detection a confidence score from:

0% = terrible / not trustworthy
100% = very strong / clean detection

Then FabScan compares that score to your Min Conf setting.

For example, with:

Min Conf = 50

FabScan will allow the follow move if the detected line confidence is 50% or higher.

If the confidence is below 50%, it refuses/stops the follow step.

So in plain shop terms:

Min Conf is the "how sure does FabScan need to be before it moves?" setting.

Lower number = more willing to keep going.

Higher number = more cautious.

Important detail

The confidence is not a true accuracy percentage.

It does not mean:

50% confidence = 50% position accuracy

It is more of a detection-quality score. Right now FabScan scores things like:

Is there enough visible line/edge span?
Does the detected shape look long and skinny enough to be a line?
Are there enough detected points?
Is the detected line reasonably near the camera center/search area?
Did it find a real contour/edge candidate?

So Min Conf is a filter to prevent FabScan from chasing weak/noisy detections.

What happens during Follow N

For Follow N, FabScan does this repeatedly:

Detect line/edge
Calculate confidence
If confidence < Min Conf: stop
If confidence >= Min Conf: make the X/Y move
Detect again
Repeat

So if you set:

Count = 50
Min Conf = 50

FabScan is allowed to take up to 50 steps, but it should stop early if the detected line gets too weak.

How I would think about the setting

For clean printed lines like your laser-printer test:

Min Conf 50 = reasonable / somewhat permissive
Min Conf 60 = better normal test value
Min Conf 70 = cautious

For early tests, I would probably use:

Min Conf: 60

For pushing corners or seeing what the algorithm can do:

Min Conf: 50

For real part edges where the background may be messy:

Min Conf: 60-70
One catch with square corners

Min Conf helps prevent following a bad/weak line, but it does not fully solve corner behavior.

At a square corner, FabScan may still see a very strong, confident line — but it may be the wrong side of the corner, or the intersection may confuse the fitted line direction.

That is why I think the next app improvement should probably be:

Stop Follow N if heading changes more than X degrees in one step.

Maybe default it around:

Max heading change: 70°

That would have caught or at least flagged the square-corner behavior better than confidence alone. The radius test had a max heading change around 62°, while the square test hit around 82°, so that lines up pretty nicely with what we are seeing.

One more note: your step was 0.03", but the exported segment lengths averaged around 0.032". That is fine. The move is not just the forward step; it can include side correction too, so the actual point-to-point distance can be slightly longer than the requested step.


For Line center mode, best practice is:

Put the yellow crosshair roughly on the center of the line before starting.

It does not need to be dead-nuts perfect. As long as the line is inside the search box, FabScan can usually find it. But if the line is off-center, FabScan sees that as an offset and tries to correct back toward the crosshair.

So if you start with the crosshair way off the line, the first few moves may include side correction until it gets centered.

The key limit is this setting:

Max correct = 0.015"

That means each step can only correct sideways by up to 0.015". So if the line is 0.060" away from the crosshair, FabScan cannot fix that in one step. It will either take several steps to walk back onto the line, or it may follow slightly biased/off-center for a while.

So the practical answer is:

Line inside search box = FabScan can detect it.
Line near yellow crosshair = FabScan follows it cleaner.

For starting a trace, I would put the crosshair as close to the desired line/edge as reasonably possible.

Does search box size matter?

Yes, quite a bit.

The search box is the area FabScan looks inside when trying to find the line/edge. Anything outside the box is mostly ignored.

Bigger search box

Good:

More forgiving if the line is not centered
Can see more of the line
Can handle small drift better
Better for straight/simple lines

Bad:

More likely to see unwanted marks
More likely to see both sides of a corner
More likely to get confused at intersections
More likely to pick the wrong tangent
Smaller search box

Good:

Better isolates the feature you want
Less clutter
Less corner/intersection confusion
More predictable near square corners

Bad:

Easier to lose the line
Less forgiving if calibration/correction is off
May not see enough line length to get good confidence
For your printed square tests

For the radius-corner square, a bigger search box is probably okay because the tangent changes gradually.

For the sharp square-corner square, I would try a smaller search box, because near the corner a big search box may see both legs of the corner at the same time. Then the algorithm has to decide which one is “the line,” and that is where it can get goofy.

I would try something like:

Step:        0.025" to 0.030"
Max correct: 0.010" to 0.015"
Min Conf:    55 to 65
Search px:   smaller than your straight-line setting

If you were using something like Search px = 220, I would try:

Search px: 120 to 160

especially for square corners.

My rule of thumb

For line-follow testing:

Straight line:       larger search box is fine
Radius corner:       medium search box
Sharp square corner: smaller search box
Messy real edge:     smallest box that still detects reliably

And start with the yellow crosshair close to the line/edge. It does not need to be perfect, but the closer it starts, the less corrective “hunting” FabScan has to do.
